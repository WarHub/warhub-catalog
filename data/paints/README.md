# Paint Catalog Data

Master paint catalog for miniature wargaming paints.

Generated by [`tools/WarHub.PaintCatalog.Tool`](../../tools/WarHub.PaintCatalog.Tool), in
this repository.

## Counts

This file states none. Nothing here generates them, so any number written down goes stale
silently. For paints and guarded barcodes per brand:

```bash
cd tools/acquisition && uv run warhub-data report --data ../../data
```

A published release states its own in `manifest.json` and in each document's `counts` envelope.

## Structure

```
manifest.yaml              # generation metadata: tool version, source repo, last run's brands
overrides.yaml             # manual corrections (edit this for fixes)
equivalences.yaml          # cross-brand colour matches (CIEDE2000)
brands/<slug>.yaml         # one archive per brand -- the source of truth for that brand
barcodes/<slug>.yaml       # generated manufacturer bridge ({Name}|{Set} -> ean/volumeMl)
harvest/<slug>.yaml        # generated manufacturer harvest extract (blank-fill only)
stores/<slug>.yaml         # committed retailer barcode snapshot (see below)
swatches/<slug>.yaml       # generated chart-swatch extraction (fills an empty hex)
store-sources.yaml         # which retailers may be snapshotted, and for which brand
swatch-sources.yaml        # which charts the swatch extraction reads
```

`brands/` is the roster: one file per brand, and the archive no record is ever removed from.
`manifest.yaml` lists only the brands the last run produced, which need not be all of them, so
where the two disagree `brands/` is the catalog -- it and `equivalences.yaml` are all the
publisher reads.

## YAML Schema

Each `brands/{slug}.yaml` file:

```yaml
brand: Vallejo
brandSlug: vallejo
source: Arcturus5404/miniature-paints
license: MIT
paints:
  - name: Black
    category: paint
    status: current          # current | suspected-discontinued | discontinued | delisted
    availability: unknown
    firstSeen: '2026-07-10'
    productCode: '70.950'
    ean: '8429551709507'     # optional; additionalEans carries any others the pot is sold under
    details:
      set: Model Color
      r: 35
      g: 29
      b: 29
      hex: '#231D1D'
      type: Standard
      finish: Matte
      volumeMl: 18
      container: dropper     # dropper | jar | pot | tin | spray
```

A record is never dropped. A paint that stops appearing in three consecutive full runs becomes
`status: suspected-discontinued` (the liveness ledger counts the misses), and reverts to `current`
if it comes back; either way it keeps its `firstSeen` and its barcode. `colourless: true` marks a
medium or varnish: a record with no colour to match on, as opposed to one whose colour is merely
unknown, which is what an empty hex means (`Models/PaintRecord.cs`).

`equivalences.yaml` — cross-brand colour matches via CIEDE2000 Delta E:

```yaml
thresholds:
  close: 5
  substitute: 10
equivalences:
  - source:
      brand: AK Interactive
      brandSlug: ak-interactive
      name: Black Night
      productCode: AK19303
      set: Acrylic Wash
      hex: '#101010'
    matches:
      - paint:
          brand: Scale75
          brandSlug: scale75
          name: Art Black
          set: Artist Range
          hex: '#101010'
        deltaE: 0
        tier: close
```

## Source & Enrichment

- **Primary source:** [Arcturus5404/miniature-paints](https://github.com/Arcturus5404/miniature-paints) (MIT License)
- **Volume & Packaging:** a per-`(brand, set)` table is the DEFAULT, not the last word — e.g.
  Citadel Base = 12 ml pot (`Configuration/VolumeTable.cs`). A manufacturer's own stated size
  overwrites it through the generated bridge, and `overrides.yaml` wins over both.
- **Vallejo EAN:** computed from the product code where it matches `XX.XXX` — `8429551` + the
  five code digits with the dot removed + an EAN-13 check digit (`Enrichment/EanComputer.cs`).
  A code in any other shape gets no computed barcode.
- **Retailer barcodes:** `stores/<brand>.yaml` — JAN/EAN snapshots keyed on the manufacturer's
  own item code, for brands whose own site publishes no barcode anywhere (Mr Hobby). Taken on
  demand by `gen_paint_store_barcodes.py`, configured in `store-sources.yaml`, and read offline
  by the harvest bridge. Metadata-only: they fill a blank EAN, they never add a paint.
- **Overrides:** manual corrections in `overrides.yaml`
- **Equivalences:** CIEDE2000 Delta E, cross-brand only, both thresholds INCLUSIVE: `close` is
  Delta E <= 5, `substitute` <= 10 (`Equivalence/EquivalenceFinder.cs`). `totalEntries` is written
  by the tool alongside them. Discontinued paints are matched too, in both roles.

## Updates

Data is regenerated weekly by
[`paint-catalog-update.yml`](https://github.com/WarHub/warhub-catalog/actions/workflows/paint-catalog-update.yml),
which opens a sticky PR. Merging that PR is what mints a release.
